Paper Radar — MVP Roadmap (v3)

Updated 2026-11-10 · Repo: kyeongseoplim/paper-radar · Current progress ≈ 35–40% of MVP · Project length: ~1 month

1. Final setup (all free)

Part Service Role
Website Streamlit Community Cloud Report, About & Roadmap, Settings pages; free .streamlit.app address
Login Auth0 (passwordless email code; Google as an optional second button) Confirms each member's email; free up to 25,000 monthly active users
Database Neon (free Postgres) Users, keywords, followed authors, reports; idles when unused and wakes on its own
Weekly job GitHub Actions Runs the Python job (weekly_run.py) that fetches papers, computes trends, calls Gemini and saves reports
Schedule + email Your existing n8n (Community Edition, web UI) Starts the weekly GitHub run, emails each user when it finishes, alerts the admin on failure
Summaries Gemini API Short summaries of the week's papers and trends
Paper data OpenAlex (free API key) New papers, author lookup, counts for trends

Weekly flow: n8n schedule (e.g. Monday 07:00 KST) → GitHub Actions runs the Python job → reports saved to Neon → n8n is notified → n8n emails each user → users open the site to see the full report.

2. Decisions locked in

  • One account per member. Each user has a free-text lab name; duplicates are allowed. Data is private to each user, even when two users share a lab name.
  • Login by email one-time code through Auth0, connected to Streamlit's built-in login.
  • Notifications by email + site. No Telegram.
  • No approval step. Emails are sent automatically once testing is finished. Until then, a test mode sends every email to the admin only.
  • Gemini for summaries. Use the paid tier before real users join (the free tier may use prompts to improve Google's products).
  • Followed person is confirmed by the user at sign-up (the exact OpenAlex profile), not picked automatically.

3. Data to store

  • Users: email, name, lab name, email on/off.
  • Keywords: 2–3 per user.
  • Followed author: OpenAlex ID, display name, institution.
  • Reports: one per user per week (data, Markdown and email version, when it was emailed).
  • Seen papers: so the same paper isn't reported twice.
  • Run log: when each weekly run started and finished, successes and failures.

Every page and query only reads the logged-in user's own rows. Public OpenAlex results can be cached and shared between users with the same keywords.

Goal: a member logs in, registers keywords and a person, and sees this week's saved report.

Goal: the weekly cycle runs and emails users without anyone touching it.

7. Free-tier limits to keep in mind

Service Limit Effect on this project
Streamlit Community Cloud Sleeps after 12 hours without visitors; ~1 GB memory; no custom domain First visit after a quiet period takes a moment to load
Neon Small storage and monthly compute allowance; idles after 5 minutes Far more than needed; first request after idle is slightly slower
Auth0 25,000 monthly active users No concern
GitHub Actions Scheduled workflows in inactive repos can be turned off after 60 days Not an issue: n8n starts the run, and the repo is active during the project
Gemini free tier Rate limits; prompts may be used by Google Fine for testing; switch to paid before real users
OpenAlex $1/day free usage with a key One weekly batch + shared cache stays well within it
n8n Runs only while your n8n deployment is up Check it is online at the scheduled time

8. Risks to watch

Risk Mitigation
Wrong author (people with the same name) User confirms the exact profile at sign-up and in Settings
Emails landing in spam Use a proper sender address; check spam folders during the pilot
Gemini outage or model name changes Model name kept in config; send the report without a summary if it fails
Automatic sending mistakes Test mode, manual test runs, and an admin alert after every run
A service changes its free plan All parts are standard (Postgres, OIDC login, SMTP), so each can be swapped without a rewrite
